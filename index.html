Multi-agent · MCP

MCP Multi-Agent Assistant

A multi-agent system where every agent reaches its tools over the Model Context Protocol — three servers unified behind one client across stdio and streamable-HTTP transports, including one I wrote with FastMCP. Agent state is checkpointed to PostgreSQL, so a run resumes by thread ID after a process restart. Research

My research sits on the measurement side of machine learning. A model reports a number; the number is trusted; and often the number was produced by something other than the ability it claims to measure — a feature that leaked information from the future, a metric that flatters a classifier on an imbalanced dataset, an evaluation split that was never really held out. My published and in-review work has been about pinning down when that happens and how to build benchmarks that resist it.

I think agentic systems are where this problem is about to get much worse. A multi-agent run touches retrieval, tool calls, and persistent state across many steps, and we currently score it as a single success or failure. That hides almost everything worth knowing: which agent went wrong, whether a benchmark was contaminated by training data, whether a run that "succeeded" did so for the wrong reason, and how partial progress should count. Building the evaluation methodology these systems lack is the direction I want to take next.

Current interests

  • Evaluation methodology for autonomous agents — metrics for partial and compounding failure, contamination-aware benchmarks, replayable runs
  • Fault attribution in multi-agent systems — identifying which agent, tool call, or piece of retained state caused a failure
  • Data leakage and reproducibility — leakage-aware protocols for graph-structured and temporal data
  • Class imbalance in high-stakes detection — fraud, illicit transactions, and the accuracy paradox
  • Retrieval and memory — grounding, context management, compression, and what agents should retain or forget
